# 第四阶段验收报告

验收日期：2026-11-02。项目版本：`1.0.0-SNAPSHOT`。

## 1. 完成内容

- 创建订单时在同一事务中执行库存条件扣减、订单保存和幂等键关联；多商品按固定编号顺序扣减。
- 待付款或已付款订单取消时回补库存，已发货和已完成订单保持原有状态机限制。
- 客户端可用 `Idempotency-Key` 安全重试：相同请求返回原订单，不重复扣库存；相同键对应不同请求返回 409。
- 新增 Flyway V3 迁移，标记第三阶段旧订单未预占库存，避免其取消时错误加库存。
- 保留第二、三阶段的预览、商品/优惠券查询、订单查询及金额规则。

接口与迁移说明见[第四阶段交易文档](transactional-checkout.md)。

## 2. 构建与测试

使用 Java 17、Spring Boot 3.5.16、MyBatis Starter 3.0.5、Flyway 11.7.2、H2 2.3.232 与原生 MySQL Community Server 8.4.13。

在独立的 `order_settlement_test` 库中设置 `MYSQL_TEST_URL`、`MYSQL_TEST_USERNAME`、`MYSQL_TEST_PASSWORD` 后执行：

```powershell
mvn -B -ntp -Pmysql-it clean verify checkstyle:check spotbugs:check
```

| 检查 | 结果 |
|------|------|
| 干净构建、Flyway 迁移与可执行 JAR 打包 | BUILD SUCCESS |
| Surefire 常规测试 | 201 次通过，失败/错误/跳过均为 0 |
| Failsafe 原生 MySQL 测试 | 33 次通过，失败/错误/跳过均为 0 |
| Checkstyle | 0 项违规 |
| SpotBugs | 0 项缺陷、0 项分析错误 |

常规测试保留第三阶段的 182 次执行，新增 19 次第四阶段测试。MySQL 端增加并发库存、幂等和应用事务回滚测试，另外复用第三阶段持久化场景；两个环境累计 234 次执行，不能理解为 234 个不同业务用例。

关键验证包括：

- 两个不同订单同时争购剩余 20 件商品、各请求 15 件，只有一个成功，最终库存为 5；没有负库存或第二笔订单。
- 同一幂等键被并发使用时，两个请求返回同一订单，只扣库存一次；不同请求复用相同键返回冲突。
- 待付款和已付款订单取消回补库存；重复取消、已发货后取消不能重复回补。
- 多商品扣减与回补、价格变动后重试仍返回原订单快照、首次失败后幂等键可再次使用。
- 订单入库失败时，库存扣减与幂等占用记录一起回滚。
- 文件数据库关闭并重启应用后，幂等键与库存状态仍然有效。
- 从 V1/V2 的真实旧表与旧订单升级到 V3 后，取消未扣过库存的旧订单不会额外加库存。

MySQL 验收使用官方便携版，在回环地址和独立临时目录中运行，没有安装系统服务或连接现有业务库。原生集成测试覆盖 MySQL 的行锁、唯一约束、事务回滚与迁移；迁移升级旧库的专项测试使用 H2 文件数据库。
